# P1-R3 头像文件选择与上传测试

关联：Issue #26；需求基线 0.1.2；FR-01、AC-10、AC-11；T-01、T-02、T-03。

## 文件约束

- Windows Electron 原生文件选择器；支持 JPEG/JPG、PNG、WebP。
- 单文件最大 10 MiB；取消选择不触发上传。
- 上传通过已认证的 `POST /api/v1/users/me/avatar` multipart 请求，字段名 `avatar`。
- API 验证实际文件签名与大小，使用服务端生成文件名存于 `data/avatars/<userId>/`；数据库只保存不含文件系统路径的 opaque key。
- `GET /api/v1/users/me` 保持统一 JSON envelope，已上传头像以 data URL 返回，既有 HTTP(S) 头像 URL 继续兼容。
- 超限、伪造 MIME/签名、未认证、存储失败或网络失败不能更改原头像；接口和日志不得返回本地原路径、服务端绝对路径或堆栈。

## D01 选图后保存丢失预览修复（2026-10-20）

- 人工复现：选择有效图片出现本地预览后直接点击“保存资料”，页面提示成功，但预览消失且所选文件仍待上传。
- 原因：保存入口仅更新昵称/URL，未调用头像上传接口；服务端旧头像又覆盖了本地预览。
- 修复：统一保存先上传所选图片，再保存昵称，省略可能清除新头像的空 URL；独立上传入口保留。读取/上传/保存期间禁用相关操作，防止并发提交。
- 失败证据：`p1-r3-evidence/final/save-profile-before-fix.txt`，真实 Electron 检查失败于 `Saving profile left the avatar selection pending`。
- 修复后结果：`save-profile-after-fix.txt` 和 `save-profile-results.json` 记录 5/5 通过，包括取消、直接保存后刷新/重新登录/重复保存、独立上传、保存时断网保留旧头像、伪造图片拒绝。截图为 `save-profile-success.png`、`save-profile-rejected.png`。
- 工程检查：`pnpm lint`、`pnpm test`（123/123）、`pnpm --filter @scpc/desktop typecheck`、`pnpm --filter @scpc/desktop build` 及脚本语法检查通过。相较首次 4 场景复测，补充保存入口的真实用户操作路径；FR-01/AC-11 修复后复测通过，仍等待项目组长人工复核。

## D02 顶部账号区未显示保存头像（2026-10-20）

- 人工发现：资料页头像保存成功，但项目页顶部仍显示昵称首字；AppLayout 原先没有图片展示分支。
- 修复：会话层在登录/刷新后读取头像，并在保存资料与独立上传成功时同步；AppLayout 使用圆形图片显示，缺失/加载失败时保留昵称首字。头像只保存在内存，不进入 sessionStorage；按用户 ID 和请求版本防止过期响应污染新头像。
- 修复前：`header-avatar-before-fix.txt` 记录真实 Electron 等待顶部图片超时；修复后：`header-avatar-after-fix.txt`、`header-avatar-results.json` 记录 6/6 通过，截图见 `header-avatar.png`。
- 覆盖：直接保存与独立上传后的顶部图片内容及解码、刷新、重新登录、切换无头像账号、头像不写入 sessionStorage，同时回归取消、断网和伪造图片拒绝。
- 工程检查：全量测试 123/123、全仓 typecheck、lint、桌面 build 与回归脚本语法检查通过。FR-01/AC-11 的 D01/D02 修复已完成，仍等待项目组长人工复核；P2 未解锁。
