## 审查发现与修复

采用 review-bugbot、review-security 方法审查本分支相对远程 main 的完整变化，未使用其他智能体。

| 检查发现 | 修复与回归 |
| --- | --- |
| 条件更新头像后读取资料发生异常时，已写入的标识可能无法回滚 | 更新与读取纳入 Prisma 事务；真实 SQLite 注入读取失败，确认旧头像标识保持不变 |
| 上传只限制文件大小，多余表单字段可越过总资源边界 | 限制一个文件、零额外字段；接口拒绝额外字段并保持旧头像 |
| 内容签名正确但损坏的图片可在客户端被上传 | 自动上传前先用浏览器解码；有效 PNG 签名但无法解码的图片不发上传请求，并恢复旧预览 |
| 通用 413 被错误提示为头像大小超限 | 头像提示仅适用于头像上传路径；普通接口 413 保持通用内容超限错误 |
| 成功提交后再次读头像文件可能受另一个客户端覆盖清理影响 | 上传响应直接使用已校验的上传数据生成图片快照，避免提交后的文件读取竞态 |

前两项修复前回归失败已保留在 `review-before-fix.txt`，修复后接口回归全部通过。当前范围内没有遗留的已确认 P1/P2 阻断缺陷。

真实窗口覆盖：

1. 文件上传是唯一头像设置方式；URL 输入和手动上传按钮不存在。
2. 取消选择不上传，已有头像保持不变。
3. 选图后自动且仅上传一次；未保存昵称既不提交也不丢弃；保存昵称不再次上传。
4. 页面刷新、退出重登、重复保存和顶部头像同步均正确，头像数据不写入 sessionStorage。
5. 相机鼠标与键盘可操作；空文件、不支持格式、超过 10 MiB 及无法解码的图片被拒绝。
6. 上传期间控件禁用；网络失败保留旧头像、避免资料 PATCH。
7. 改密旋转 Token；旧 Token 401、新 Token 200，旧密码不能登录、新密码可登录，头像仍保留。
8. 切换无头像账号显示该账号首字，不残留上一用户图片。

以上为 9 组运行中的主要断言；同组包含多个相关步骤。使用独立 SQLite、临时 API 端口和随机账号，未使用人工测试账号凭据或数据库。`profile.png`、`header.png`、`rejected.png` 为合成测试账号的实际截图。

## 兼容、风险与交付边界

- 没有新增依赖或 Schema/Migration；既有 HTTP(S) 头像值仍可读取，但界面只提供自动文件上传。
- 服务端按内容签名识别类型；客户端负责图片解码，不进行服务端图片重编码。真实窗口使用 PNG；JPEG/WebP 签名识别由单元测试覆盖。
- 最大 10 MiB 图片以内联 data URL 返回资料，响应约 13.3 MiB。Release 打包前仍需验证可写、持久的头像目录、打包后 API 启动和物理跨设备访问；这些属于后续发布验收。
- 仓库当前未配置 GitHub Actions 工作流；本报告为已执行的本地门禁，不将无 CI 检查解释成远程 CI 通过。
- 回滚前备份数据库及头像目录。代码回滚不删除已保存的图片；`uploaded:` 引用需配套新版服务读取，完整回退旧版时应恢复备份或执行单独审批的数据恢复。

本报告与门禁文档通过功能分支 PR 交付；PR 创建不等于合并。
