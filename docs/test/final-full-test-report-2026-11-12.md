- 从冻结main归档中解压源码，`pnpm install --frozen-lockfile --offline`成功，501个包按锁文件安装，未升级依赖。该环境首次缺少原生运行文件，首次Prisma生成等待被中止，保留输出；在本机代理下重建已批准依赖并执行锁定Electron的安装脚本后，Prisma生成和 `pnpm build` 成功，新Electron实际可启动。

首次新增脚本曾误要求错误数据库在启动时失败，已对照PrismaService的延迟连接实现，改为验证真实请求的安全失败；原失败不计作产品缺陷。首轮恢复测试依赖前一步所在页面，已改为先明确导航到概览后再测试重启，定向复测通过。

## 4. FT-F01 万任务看板交互响应慢

- 关联：FR-05/FR-11、AC-09及需求第9.1节容量和性能；清单FT-13。级别P2，状态**待排查修复与复测**，正式结项前需处理决定。
- 复现：独立源码构建启动标准Electron，项目包含10,000条TODO任务，进入看板，在标题搜索输入 `capacity-000` 并应用筛选。
- 现象：两轮自动点击等待超过15秒，失败截图已显示筛选结果100条；改为真实坐标鼠标点击后，筛选及100行实际下载正确，但筛选耗时29,772ms。不能将这些超时简单等同于筛选逻辑错误，也不能仅凭最终结果正确判为性能通过。
- 环境对照：原进程继承工具设置 `ELECTRON_FORCE_RENDERER_ACCESSIBILITY=1`；在新子进程中移除该设置后，仍出现15秒输入超时。因此目前不能把问题仅归因于工具强制辅助功能。未改变系统全局设置或Electron安全选项。
- 已知事实：API列表和筛选正常；DOM实测10,000卡片和10,008按钮；[BoardPage](../../apps/desktop/src/renderer/src/pages/BoardPage.tsx)将筛选输入状态及全量卡片渲染放在同页。全量DOM与重渲染是排查方向，具体耗时来源仍需进一步分析，未宣称已确定根因。
- 后续：组长人工测试M-12重点复核输入、筛选和等待时间；root根据复现证据处理性能问题，修复后重复同规模、同数据及普通场景回归。不在本轮测试中擅自改产品或降低断言。

其他已知限制仍保留：部分最近动态显示英文动作编码；已有验收日期不能直接清空，界面会明确提示。未把这些项目描述为已修复。
