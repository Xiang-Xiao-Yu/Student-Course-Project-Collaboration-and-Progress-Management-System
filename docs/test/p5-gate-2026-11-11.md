## 已修复阻塞：新建验收绕过整改任务的切换锁定

严重程度：P2。关联 FR-09、AC-07。

### 复现与实际结果

1. 在原验收 A 中创建整改任务 T，并选择迭代。
2. 分别在加入迭代请求进行中、加入失败待重试两个时机，检查验收列表按钮与“创建阶段验收”。
3. 列表按钮已禁用，但创建按钮仍可用。填写并创建验收 B 后，页面自动切换到 B。
4. B 的详情下仍显示 A 的待处理任务 T、“查看已创建任务”和重试入口；并发请求失败提示也可能显示在 B 下。
5. 真实 API 查询确认 A 有 1 条整改任务、B 有 0 条，界面链接指向 A 的任务。确认的是界面状态归属错误，未观察到数据库将 T 改关联到 B。

两种时机均成功复现；首次不依赖网络故障注入，只需页面加载后取消所选迭代；提交中场景通过延迟加入迭代响应复现。

### 根因与最小修正建议

文件：`apps/desktop/src/renderer/src/pages/AcceptancesPage.tsx`。

- 第 658 行创建按钮仅使用 `disabled={isCreating}`，未遵守列表使用的 `selectionLocked`。
- 第 298 行 `handleCreate` 也仅检查 `isCreating`；第 320～327 行会自动激活新创建记录。
- 第 918 行待处理任务块只判断 `pendingRemediationTask` 是否存在，未按 `acceptance.id` 与 `pendingRemediationTask.acceptanceId` 限定归属。

建议创建入口与处理函数共用切换限制；待处理区域增加验收 ID 归属校验。应覆盖整改提交中、待重试、普通创建成功以及既有创建锁/重试恢复场景。不得通过清空待处理任务或移除错误提示掩盖问题。

之前的并发回归验证了列表切换和创建请求期间列表禁用，未覆盖反方向的“整改操作期间新建验收”。初次核查只检查并保存证据，未修改业务实现；后续经项目组长要求解决，实施了下述修复。
