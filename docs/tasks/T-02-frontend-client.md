## 认领规则

认领时必须由智能体使用自己的名称化标签，例如 `ChatGPT@frontend`，并向 `root` 报告。只有 `root` 确认后，负责人标签、分支和 PR 才生效。认领后只能修改本任务允许的前端文件和本文件的进度/验证/交接区域。

## 任务边界

本任务负责桌面客户端页面、路由、状态管理、表单校验、API 调用、加载/空状态/错误状态和键盘可用性。不得修改后端 Schema、Migration、依赖清单、认证授权策略、公共 API 契约或其他任务文件。

## 阶段与小功能

必须与 `T-01` 使用同一阶段顺序。当前阶段完成后，`T-02` 必须标记 `待测试` 并停止开发；待 `T-01` 也完成后，全员冻结，由 `T-03` 统一验证。测试通过且 `root` 明确解锁后，才能开始下一阶段。测试失败时只能修复当前阶段，修复后再次冻结并交由 `T-03` 复测。

阶段门禁状态：`开发中 → 全员待测试 → 全员冻结 → T-03 检查中 → 检查失败/当前阶段修复 → T-03 复测 → root 解锁下一阶段`。

### P0 基础客户端

- P0 的客户端地址、API 前缀、响应格式、Token 传递和错误展示以 [P0 工程与契约约定](../P0-工程与契约约定.md) 为准；T-02 不得自行修改共享契约。
- P0.1 建立 Electron 窗口、React 入口、路由骨架和统一布局。
- P0.2 建立 API client、token 生命周期处理和统一错误提示。
- P0.3 建立加载、空数据、失败和未保存表单提示组件。
- 门禁：应用可启动；未登录访问项目页被拦截；接口失败不崩溃。

### P1 登录与个人资料

- P1.1 注册、登录、退出和会话过期页面。
- P1.2 重复用户名、密码错误、禁用用户和 token 失效提示。
- P1.3 个人资料和个人负责任务入口。
- 门禁：对应 AC-01，覆盖正常、边界和失败场景。

### P2 项目、成员与权限界面

- P2.1 项目列表、创建、编辑、状态和归档确认。
- P2.2 成员列表、角色设置、邀请和移除确认。
- P2.3 按角色隐藏不可用操作，但不把前端隐藏当作权限校验。
- 门禁：对应 AC-02、AC-08；覆盖空项目、无权限返回、无效日期和删除确认。

### P3 需求、任务与看板

- P3.1 需求列表、创建/编辑、验收标准和关联任务。
- P3.2 任务创建/编辑、负责人、优先级、截止日期、标签和需求关联。
- P3.3 看板拖拽和状态流转，包括待审核、已阻塞、完成说明和重新打开原因。
- P3.4 任务详情的评论、操作记录和完成时间展示。
- 门禁：对应 AC-03、AC-04；覆盖拖拽失败、校验提示、越权错误和状态回滚。

### P4 迭代、评论与记录

- P4.1 迭代列表、创建、任务加入/移出和关闭。
- P4.2 迭代统计卡片及逾期标记。
- P4.3 评论编辑/删除和活动记录时间线。
- 门禁：对应 AC-05；覆盖空迭代、组合统计和评论权限。

### P5 会议与阶段验收

- P5.1 会议列表、会议详情、议程、纪要和决定。
- P5.2 行动项负责人、截止日期、状态和转任务操作。
- P5.3 阶段验收创建、未通过原因、整改任务和再次验收。
- 门禁：对应 AC-06、AC-07；覆盖表单边界、无权限和失败提示。

### P6 仪表盘、筛选与导出

- P6.1 仪表盘指标和 ECharts 图表加载状态。
- P6.2 任务趋势、燃尽图、筛选条件组合和清空筛选。
- P6.3 CSV 导出和基础项目进度报告入口。
- 门禁：对应 AC-09、AC-10；覆盖空数据、无结果、网络失败和导出失败。

## 不在本任务范围

- 不实现实时协作、聊天、移动端、AI 自动拆解、GitHub 双向同步和复杂通知中心。
- 不修改 `package.json`、锁文件、Prisma 文件、后端权限和其他智能体的文件。

## 交付与验收

- 页面必须使用 TypeScript 严格类型和 React 函数组件。
- 每个阶段交付页面、交互说明、截图或录屏（如有界面变化）和测试结果。
- 测试未通过时只修复本任务范围内的问题；跨任务问题提交给 `root`，不得自行修改。
- 当前阶段进入全员冻结后不得继续开发，不得提前制作下一阶段页面；测试失败只能按 `root` 指定范围修复当前阶段。
