## 负责人规则

本任务由 `ChatGPT@root` 负责。其他智能体只能阅读测试任务、提交 Issue 或提供测试证据，不得修改本任务的测试、报告、阶段门禁和进度记录。

## 任务边界

本任务负责测试计划、测试用例、自动化测试、接口/权限验证、阶段回归和验收报告。不得修改业务实现来制造测试通过，不得降低校验标准，不得删除失败测试；发现实现问题时向 `root` 提交证据和建议。

## 阶段与小功能

测试必须跟随当前阶段执行。当前阶段的 `T-01` 和 `T-02` 都标记 `待测试` 后，三人进入全员冻结；`T-03` 统一执行当前阶段的正常、边界、失败和权限检查。检查期间任何人不得开始下一阶段。测试失败时保持冻结，由 `root` 指定当前阶段修复范围；修复后 `T-03` 必须复测。只有 T-03 报告通过且 `root` 明确解锁，才能进入下一阶段。

阶段门禁状态：`开发中 → 全员待测试 → 全员冻结 → T-03 检查中 → 检查失败/当前阶段修复 → T-03 复测 → root 解锁下一阶段`。

### P0 测试基础

- P0 的启动命令、健康检查、响应格式、环境变量和数据库约定以 [P0 工程与契约约定](../P0-工程与契约约定.md) 为测试基线。
- P0.1 建立测试目录、命名规则、测试数据策略和报告模板。
- P0.2 建立启动检查、统一错误格式和最小健康检查。
- P0.3 记录测试环境、命令、结果和阻塞问题。
- 门禁：测试命令可重复执行；失败能定位到具体模块和场景。

### P1 认证测试

- P1.1 正常：注册、登录、退出和会话过期。
- P1.2 边界：密码长度、用户名边界、重复用户名。
- P1.3 失败/安全：错误凭据、禁用用户、旧 token、未登录访问。
- 门禁：AC-01 全部通过。

### P2 项目、成员与权限测试

- P2.1 正常：创建项目、邀请两名成员和查看项目。
- P2.2 边界：日期相等、暂停恢复、空成员和移除成员后历史记录。
- P2.3 失败/安全：跨项目读取、普通成员删除项目、观察者写入、负责人自移除。
- 门禁：AC-02、AC-08 全部通过。

### P3 需求、任务与状态流测试

- P3.1 正常：创建需求、添加验收标准、创建多个关联任务。
- P3.2 边界：标题长度、无负责人、截止日期、阻塞和待审核。
- P3.3 失败/安全：越权修改、无完成说明完成、错误状态跳转、重新打开无原因。
- 门禁：AC-03、AC-04 全部通过，ActivityLog 可追溯。

### P4 迭代、评论与统计测试

- P4.1 正常：创建迭代、加入任务并计算完成率。
- P4.2 边界：空迭代、逾期任务、阻塞任务和组合统计。
- P4.3 失败/安全：评论修改他人内容、删除他人评论、越权查看记录。
- 门禁：AC-05 及相关 FR-06/FR-07 场景通过。

### P5 会议与阶段验收测试

- P5.1 正常：会议、纪要、行动项、转任务和通过验收。
- P5.2 边界：空标题、截止日期、行动项状态、再次验收。
- P5.3 失败/安全：无权限验收、未通过缺少原因、转换失败后数据一致性。
- 门禁：AC-06、AC-07 全部通过。

### P6 仪表盘、筛选与导出测试

- P6.1 正常：指标、图表、组合筛选和 CSV 导出。
- P6.2 边界：空项目、无结果、日期边界和大列表分页/查询。
- P6.3 失败/稳定性：无效参数、网络请求失败、导出失败、图表加载失败。
- 门禁：AC-09、AC-10 全部通过。

### P7 MVP 回归与验收报告

- P7.1 执行核心流程：创建项目 → 建需求 → 拆任务 → 执行 → 验收 → 统计。
- P7.2 执行角色矩阵、数据隔离、输入校验、日志脱敏和错误信息检查。
- P7.3 汇总测试报告、未完成项、风险、回滚建议和最终验收结论。
- 门禁：所有 M 功能通过；未通过项必须明确责任任务和处理决定。

## 不在本任务范围

- 不修改后端、前端或数据库实现来绕过失败测试。
- 不替其他智能体认领、转移、拆分或关闭任务。
- S/C 功能只做范围核对，不得抢先实现。

## 交付与验收

- 每个阶段至少有一个正常、一个边界和一个失败场景。
- 测试报告必须包含命令、真实结果、失败原因、影响范围和复测结果。
- 只有 `root` 可以根据测试报告确认阶段门禁通过或决定暂停。
- `T-03` 在统一检查期间不能自行修改业务实现；发现问题必须记录 Issue、证据和责任任务。
- 测试未通过时不得宣布阶段完成，也不得允许任何人开始下一阶段。
