# P4 评审问题修复计划

> 对照 FR-06、FR-07、AC-05、AC-10；保持现有技术栈和数据库结构。

## 范围与接口

- 迭代任务加入请求携带用户看到的任务来源（无来源用 null），服务端在事务中比较实际归属；不匹配时返回明确冲突，不能覆盖他人的安排。
- 已完成或已取消迭代中的未完成任务允许迁出；已完成任务和终态目标仍受保护。关闭迭代的已有迁移行为保留。
- 前端使用与后端相同的上海日历日判断，并保护迭代编辑和评论草稿；异步操作只能更新所属迭代的统计状态。
- 终态页面只提供有效操作，避免提交必然失败的请求。

## 验证步骤

1. 补充真实 SQLite/HTTP 后端回归：终态未完成任务迁移、已完成任务限制、来源被并发改变时拒绝写入。
2. 补充前端回归：时间戳跨上海日期、未保存编辑及评论离开、旧请求不会清除当前错误、终态操作。
3. 分别运行相关测试并确认修复前失败、修复后通过；运行完整测试、lint、typecheck、build。
4. 复查完整差异及当前 PR 提交；按 #42、#43 顺序合并并核实最终状态。
