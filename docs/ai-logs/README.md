# AI 智能体日志规范

## 1. 目的

记录每个智能体对项目需求、代码、文档、数据库、接口和工程配置做出的重要决定，保证改动可以追溯、复查和交接。

## 2. 文件约定

- 每个智能体使用独立文件夹，每天在自己的文件夹中新建日志：`docs/ai-logs/<agent-id>/YYYY-MM-DD.md`。
- 当天的后续日志追加到当天文件；进入新日期后必须新建日期文件，不得继续写入前一天文件。
- 主智能体使用 `docs/ai-logs/root/YYYY-MM-DD.md`。
- `<agent-id>` 使用稳定、简短、只含小写字母、数字和连字符的名称，例如 `root`、`frontend`、`backend`、`qa`。
- 每个智能体只能写入自己的日志文件夹，不得修改其他智能体的日志。
- 不要把多个智能体的记录合并到一个文件，不要覆盖、删除或重命名历史日志。
- 原 `root.md` 的历史内容已合并到 `docs/ai-logs/root/2026-09-20.md`；后续按智能体文件夹和日期文件记录。

## 3. 必须记录的事项

智能体开始处理以下事项前，先记录计划：

- 新功能或需求变更；
- 架构、数据库、接口、权限和安全策略变化；
- 新增或升级依赖；
- 配置、构建、部署和 CI 变化；
- 文件移动、删除、批量重命名或其他不可逆操作。

完成后在当天的智能体日志文件中补充：实际改动、验证命令、测试结果、遗留风险和交接事项。

普通拼写修正、格式化或不影响行为的局部调整，可以在当天的汇总条目中记录。

## 4. 日志模板

```markdown
## YYYY-MM-DD HH:mm — 简短标题

- 智能体：root
- 类型：需求 / 设计 / 实现 / 测试 / 配置 / 安全 / 决策
- 需求引用：FR-xxx、AC-xxx；没有时写“文档维护”
- 目标：本次要解决什么问题
- 计划文件：列出预计修改的文件
- 实际文件：列出实际修改的文件
- 变更摘要：做了什么，以及为什么这样做
- 验证：执行的命令和结果
- 风险与遗留：已知问题、未完成事项或回滚方式
- 下一步：后续动作或交接信息
```

## 5. 日志安全

- 不记录密码、API Key、JWT、GitHub Token、Cookie、完整路径中的隐私信息或完整用户数据。
- 日志应引用需求编号和提交号，不复制大段代码。
- 日志和对应代码或文档必须在同一逻辑提交或同一个 PR 中保持同步。
