# AI 智能体日志规范

## 1. 目的

记录每个智能体对项目需求、代码、文档、数据库、接口和工程配置做出的重要决定，保证改动可以追溯、复查和交接。

## 2. 文件约定

- 本目录仅保留三个主要智能体目录和本说明文件：

| 目录 | 主要智能体 | 职责 |
|---|---|---|
| `root/` | ChatGPT@root | 统筹、评审、验收与临时智能体交接摘要 |
| `codex-backend/` | Codex@backend | 后端与数据契约 |
| `deepseek-frontend/` | Deepseek@frontend | 前端与客户端 |

- 主要智能体每天使用自己目录中的 `YYYY-MM-DD.md`；当天追加，进入新日期后新建文件，不继续写入前一天文件。
- 临时评审、测试和辅助智能体不新增日志目录或独立日志文件；开始前与结束后向 root 交接，由 root 记录任务标签、目标、结论、验证结果和证据位置。不要复制整份临时过程日志。
- 临时智能体不得写入三个主要智能体的日志。主要智能体也不得修改其他主要智能体的日志。
- 主要智能体历史日志保持只读，不合并、覆盖、删除或重命名。项目组长明确要求清理临时日志时，由 root 先做可恢复备份并保留历史溯源，再按确认范围整理。
- 正式测试报告、原始输出与截图仍按任务授权保存在 `docs/test/` 等位置，不因日志目录收敛而移除。
- 原 `root.md` 的历史内容已合并到 `docs/ai-logs/root/2026-09-20.md`；后续按智能体文件夹和日期文件记录。

## 3. 必须记录的事项

主要智能体开始处理以下事项前记录计划；临时智能体向 root 交接，由 root 记录：

- 新功能或需求变更；
- 架构、数据库、接口、权限和安全策略变化；
- 新增或升级依赖；
- 配置、构建、部署和 CI 变化；
- 文件移动、删除、批量重命名或其他不可逆操作。

完成后在当天的主要智能体日志中补充：实际改动、验证命令、测试结果、遗留风险和交接事项；临时智能体由 root 汇总，仍保留具体任务标签和证据来源。

普通拼写修正、格式化或不影响行为的局部调整，可以在当天的汇总条目中记录。

## 4. 日志模板

```markdown
## YYYY-MM-DD HH:mm — 简短标题

- 智能体：root
- 类型：需求 / 设计 / 实现 / 测试 / 配置 / 安全 / 决策
- 需求引用：FR-xxx、AC-xxx；没有时写“文档维护”
- 目标：本次要解决什么问题
- 计划文件：列出预计修改的文件
- 实际文件：列出实际修改的文件
- 变更摘要：做了什么，以及为什么这样做
- 验证：执行的命令和结果
- 风险与遗留：已知问题、未完成事项或回滚方式
- 下一步：后续动作或交接信息
```

## 5. 日志安全

- 不记录密码、API Key、JWT、GitHub Token、Cookie、完整路径中的隐私信息或完整用户数据。
- 日志应引用需求编号和提交号，不复制大段代码。
- 日志和对应代码或文档必须在同一逻辑提交或同一个 PR 中保持同步。
