## 1. 目的与范围

本文集中整理 FR-01～FR-11、AC-01～AC-11 的验证安排及已有阶段结果，为结项资料提供可追溯入口。本次同步实际执行的最终技术回归；历史阶段结果各自保留版本边界。

阶段报告绑定各自版本、环境和场景，覆盖有重叠，测试数量不相加为全项目唯一用例总数。早期发现和环境限制应结合后续复测说明，不将历史失败直接作为当前阻塞，也不删除其原始证据。

## 2. 测试组织与环境

### 2.1 验证层次

| 层次         | 目标                                    | 主要检查方式                                   |
| ------------ | --------------------------------------- | ---------------------------------------------- |
| 静态质量     | 类型、格式、代码规范和日志布局正确      | typecheck、ESLint、Prettier、日志检查          |
| 单元与组件   | 业务规则、算法及交互分支正确            | Vitest 及已有测试                              |
| 数据与接口   | DTO、认证授权、关联、事务和异常处理正确 | 隔离 SQLite、真实 Nest HTTP                    |
| 标准桌面联调 | 实际页面、API 和数据一致                | 标准 Electron、真实 API、隔离 profile 与数据库 |
| 人工体验     | 操作入口、提示和流程是否清楚            | 原人工测试指南及匿名观察记录                   |
| 最终回归     | 核心流程、权限、安全与验收资料完整      | P7 冻结版本及正式结果记录                      |

### 2.2 环境与数据要求

目标客户端为 Windows 11；Node.js、pnpm 和 Electron 使用工程锁定版本。实际执行时记录操作系统、运行文件、提交号、API 地址、迁移状态和数据规模。历史报告的真实环境保留原样，不统一改写为目标环境。

测试使用合成账号、独立数据库及客户端 profile，不在用户现有业务库上制造测试数据。凭据通过运行环境提供，报告和截图不保存密码、完整令牌、密钥或未脱敏隐私。

## 7. 性能与其他非功能目标

| 需求目标                    | 最终报告需记录的证据                                          |
| --------------------------- | ------------------------------------------------------------- |
| 普通页面首次加载不超过 3 秒 | 页面、冷暖启动条件、设备、网络、数据规模及测量结果            |
| 常规任务查询不超过 1 秒     | 查询条件、数据量、端到端或服务端边界及结果                    |
| 至少 20 名用户同时访问      | 用户或请求模型、并发持续时间、成功失败及响应情况              |
| 单项目至少 10,000 条任务    | 数据规模、实际操作及测量边界，不能只用内存算法耗时代替        |
| 可用性及兼容性              | 加载空态、失败恢复、键盘操作、目标 Windows 环境与实际运行模式 |

P6 中的专项性能修复及大数据检查不能自动证明所有端到端性能、并发和容量目标已完整达标。最终测试报告应补充实际证据或明确未验证范围，不能将需求值直接填入“实测结果”。
