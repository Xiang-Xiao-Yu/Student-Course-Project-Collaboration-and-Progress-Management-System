## 2. 运行时与包管理器

- 操作系统基线：Windows 11。
- Node.js：`24.18.0`，后续升级必须先提交依赖或配置变更 Issue。
- 包管理器：`pnpm@11.21.0`。
- 所有依赖由根目录 workspace 统一管理，提交 `pnpm-lock.yaml` 后，安装使用 `pnpm install --frozen-lockfile`。
- 禁止在 T-01、T-02 中各自创建独立锁文件、替换包管理器或直接升级依赖。

## 3. 目录与任务边界

```text
apps/
  api/                 # NestJS API 服务，由 T-01 负责
  desktop/             # Electron + React 客户端，由 T-02 负责
packages/
  shared/              # API DTO、枚举和共享类型，由 T-01 维护
prisma/
  schema.prisma        # Prisma Schema，由 T-01 负责
  migrations/          # Prisma Migration，由 T-01 负责
  seed.ts              # 开发种子，由 T-01 负责
data/                  # 本地 SQLite 文件，不进入 Git
tests/                 # 跨模块测试与测试报告，由 T-03 负责
docs/                  # 需求、契约、测试和交付文档，由 root 管理
```

文件权限约定：

- `root` 负责根目录 `package.json`、`pnpm-workspace.yaml`、锁文件、环境变量模板、需求基线、P0 共享契约、任务范围和阶段解锁记录。
- T-01 负责 `apps/api/`、`packages/shared/`、`prisma/` 及其获准的后端测试。
- T-02 负责 `apps/desktop/`，只能消费已确认的共享契约。
- T-03 负责 `tests/`、测试报告和质量记录，不修改业务实现制造测试通过。
- T-01/T-02 负责人可以修改自己任务文档中的进度、验证和交接区域，以及任务边界内的实现文件；不得修改其他任务目录、根配置、需求基线、P0 共享契约或任务范围。
- 任何跨任务调整、公共契约变化或超出授权范围的修改，都必须使用 GitHub Issue 提交给 `root`。

## 4. 启动命令

P0 完成后必须提供以下根目录命令：

```text
pnpm install --frozen-lockfile  # 安装已锁定依赖
pnpm dev:api                    # 启动 NestJS API
pnpm dev:desktop                # 启动 Electron + React 客户端
pnpm dev                        # 同时启动 API 和桌面客户端，可选但建议提供
pnpm db:migrate                 # 执行 Prisma Migration
pnpm db:seed                    # 写入最小开发种子
pnpm test                       # 执行当前阶段测试
pnpm lint                       # 执行格式和静态检查
pnpm typecheck                  # 执行 TypeScript 严格类型检查
```

命令必须在 README 或交付说明中保持一致。命令失败时应输出可定位的模块和原因，不输出密钥、Token、数据库凭据、SQL 或完整堆栈。

## 5. 服务地址与局域网连接

| 配置 | 默认值 | 说明 |
|---|---|---|
| `APP_HOST` | `127.0.0.1` | 本机演示绑定地址；局域网部署时由 root 明确改为 `0.0.0.0` |
| `APP_PORT` | `3000` | NestJS API 端口 |
| API 前缀 | `/api/v1` | 所有业务 API 必须使用版本前缀 |
| 健康检查 | `GET /api/v1/health` | 不需要登录，只返回服务状态 |
| `ELECTRON_API_BASE_URL` | `http://127.0.0.1:3000/api/v1` | Electron API 地址；局域网客户端改为服务端局域网 IP |

局域网模式下只有 API 服务端访问 SQLite 文件。客户端不得直接打开、共享或写入 SQLite 文件；防火墙、CORS 来源和监听地址必须按实际局域网范围配置。禁止把数据库端口暴露给客户端。

## 6. 环境变量

根目录必须提供 `.env.example`，但不得包含真实凭据。`.env`、`.env.*`（`.env.example` 除外）只保存在本地。

| 变量 | 示例值 | 规则 |
|---|---|---|
| `NODE_ENV` | `development` | 允许 `development`、`test`、`production` |
| `APP_HOST` | `127.0.0.1` | 不允许从用户输入直接拼接 |
| `APP_PORT` | `3000` | 必须校验为有效端口 |
| `DATABASE_URL` | `file:../data/app.db` | 相对于 `prisma/schema.prisma` 解析 |
| `JWT_SECRET` | `replace-with-local-secret` | 必填；不得写入源码、日志或提交记录 |
| `JWT_EXPIRES_IN` | `2h` | 统一由服务端读取 |
| `CORS_ORIGINS` | `http://localhost:5173` | 只允许明确来源，禁止生产环境使用 `*` |
| `ELECTRON_API_BASE_URL` | `http://127.0.0.1:3000/api/v1` | 客户端请求基地址 |
| `LOG_LEVEL` | `info` | 日志必须脱敏 |

缺少必填密钥时，服务可以拒绝启动，但错误只能说明配置缺失，不得打印密钥内容、环境变量完整值或堆栈。

## 7. API 响应契约

成功响应统一使用：

```json
{
  "success": true,
  "data": {},
  "meta": {
    "requestId": "request-id",
    "timestamp": "2026-09-20T00:00:00.000Z"
  }
}
```

失败响应统一使用：

```json
{
  "success": false,
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "用户名或密码错误",
    "details": null
  },
  "meta": {
    "requestId": "request-id",
    "timestamp": "2026-09-20T00:00:00.000Z"
  }
}
```

约定：

- `success`、`data`、`error`、`meta` 字段名称固定，DTO 使用 TypeScript 严格类型。
- `error.code` 使用稳定的大写下划线编码，前端按编码处理，不按中文 `message` 判断业务分支。
- `message` 面向用户，不能包含 SQL、文件绝对路径、Token、密钥或服务端堆栈。
- `details` 只返回安全的字段级校验信息；生产环境不能返回内部异常细节。
- HTTP 状态码至少统一支持：`400` 参数错误、`401` 未认证、`403` 无权限、`404` 不存在、`409` 冲突、`422` 业务校验失败、`500` 服务端错误。
- 认证请求使用 `Authorization: Bearer <access_token>`；旧 Token 失效由服务端负责，不能只在前端删除本地 Token。

## 8. 数据库约定

- 数据库使用 SQLite，Prisma 是唯一数据访问层。
- 默认文件为 `data/app.db`，该目录和数据库文件不得提交到 Git。
- Schema 变更必须通过 Prisma Migration；禁止手工修改运行中的数据库结构。
- 种子数据只用于开发和测试，必须可重复执行或明确说明清理策略。
- P0 不执行删除数据的迁移；涉及不可逆变更时必须先创建 Issue，说明备份和恢复方案。
- 多个 Electron 客户端只能通过 API 访问数据库，不能共享 SQLite 文件路径。

## 9. P0 验收条件

P0 进入 T-03 检查前，必须同时满足：

1. `pnpm install --frozen-lockfile` 可重复执行。
2. API 可以启动，`GET /api/v1/health` 返回统一成功响应。
3. Electron 客户端可以启动，未登录访问业务页面会被拦截。
4. Prisma Migration 可以执行，默认数据库路径符合本文件约定。
5. 缺少 `JWT_SECRET` 或数据库配置错误时，错误信息不泄露敏感内容。
6. API 失败响应符合统一错误格式，前端能展示可理解的错误提示。
7. T-01、T-02、T-03 的测试命令、环境和结果已记录在各自允许的日志或报告中。
